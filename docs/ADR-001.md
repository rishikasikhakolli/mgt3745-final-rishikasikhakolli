# ADR-001: Travlr runs on GitHub Pages + a Cloudflare Worker with D1

Status: Proposed
Date: 2026-11-09

## Context
Travlr is a casual travel sharing app where a user posts a photo, the spot's name, and a short review, and friends scroll those cards to follow the trip without the pressure of public social media or a group chat (PROJECT.md, USERS.md). Today only the review text is stored on the server while photos and spot names stay in the poster's browser. I am one developer with six weeks, no budget, and three real users to reach.

## The Gate
Where should Travlr's code and data live? Scores: 5 = best fit, 3 = workable, 1 = blocks the project.

| Criterion | Weight | Build (Worker + D1) | Buy (Firebase) | Delegate (AI builder) |
|---|---|---|---|---|
| Cost to start | 5 | 5 | 4 | 5 |
| Cost to maintain | 4 | 5 | 2 | 5 |
| Time to working | 4 | 4 | 4 | 5 |
| Inspectability | 5 | 5 | 1 | 2 |
| Switching cost | 3 | 4 | 2 | 3 |
| Fit to spec | 4 | 5 | 3 | 3 |
| **Total** | | **118** | **67** | **96** |

Build wins since it's free, already working, and every line is mine to test. Delegate is the runner-up, but in HW5 bolt.new replaced my backend with localStorage. Even with Inspectability weighted 1, Build still wins (98 vs. 88).

## Options considered
| Option | For | Against |
|---|---|---|
| Build: GitHub Pages + Worker + D1 | Free, already works and I can read every line | I'm responsible if it breaks or data leaks |
| Buy: Supabase | Login and storage are already built, quick to set up | I'd have to redo my working code in a new tool |
| Delegate: AI builder hosts it (bolt.new) | Fastest way to a demo | In HW5 it replaced my backend without asking and I can't check what it built |
| Photos in Cloudflare R2 instead of D1 | Made for storing files like photos | More setup: a new storage space, new code to upload and show photos, and keeping photos matched to the right reviews |

## Decision
Build. The page is served from GitHub Pages in this public repository. Each review (review, spot name, and photo) goes through a Cloudflare Worker to D1 in one request. Photos are resized in the browser before upload so each row stays well under D1's roughly 2 MB row limit. localStorage is no longer used for entry data.

## Consequences
- The app can't post or load reviews without internet, so it needs clear error messages on the page.
- Photos lose some quality when they're shrunk before upload.
- I'm responsible for keeping everyone's reviews and photos safe, and anyone with the link can post without logging in.

**When I'd change this decision**
- If shrunk photos still fail to save, or the database gets close to full, I'll move photos to R2 in a new ADR.
- If traffic goes past Cloudflare's free limits, or users need their own private accounts, I'll rethink the setup.
